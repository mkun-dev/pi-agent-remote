# 系统架构

> Pi Agent iOS Remote — iOS 作为 Pi Agent 的远程终端
> 版本：1.0 ｜ 状态：Phase 1/2/3 已实现

## 1. 核心目标

iOS 用户输入：
```
帮我分析一下这个项目
```
等价于 PC 上直接输入：
```
帮我分析一下这个项目
```

消息通过 **Pi Extension API** 进入 Pi Agent Runtime，Pi 的所有事件（消息、Tool、状态、文件变化）实时同步到 iOS。

## 2. 架构图

```
iOS App (SwiftUI / PWA)
    │
    │ WebSocket (ws://PC:3001)
    │
pi-ios Extension (TypeScript / Node.js)
    │
    │ Pi Extension API
    │   ├── pi.on("turn_end", ...) → broadcast
    │   ├── pi.sendUserMessage(text) ← from iOS
    │   └── events: tool_execution_*, message_*, agent_*, session_*
    │
Pi Agent Core
    │
    ├── Tools / Shell / Files / Commands
```

## 3. 组件说明

| 组件 | 技术栈 | 职责 |
|------|--------|------|
| iOS 客户端 | SwiftUI (pi-ios-app) | 聊天 / 终端 / 时间线 / 设置 / 通知 |
| WebSocket 服务器 | `ws` 包 (src/websocket-server.ts) | 端口 3001，广播事件、接收输入 |
| 协议层 | TypeScript (src/protocol.ts) | 生成/解析 JSON 协议消息 |
| 扩展入口 | TypeScript (src/index.ts) | 监听 Pi 事件并转发，处理 iOS 输入 |
| Pi Agent | @earendil-works/pi-coding-agent | 核心 Agent 运行时 |

## 4. 消息流转

### iOS 统一事件入口（增量迁移）

```text
WebSocket Raw JSON
    ↓
RemoteEventDecoder
    ↓
RemoteEvent（Agent / Assistant / Tool / File / Session / Usage / Model / Questionnaire / Media / Relay）
    ↓
ConversationStore（O(1) 增量投影）
    ├─ messages（迁移影子状态）
    ├─ currentTrace
    ├─ activityEvents
    ├─ logs（已接管 LogsView）
    ├─ agentState
    └─ sessionState
```

迁移期间 `WebSocketManager` 通过 `RemoteEventDecodingResult` 复用同一次 JSON 解码，并继续运行旧 Message/Trace 处理链。Chat 与 Activity 暂时保持旧链，避免一次性重写造成 UI 回归；`LogsView` 已改为消费 `ConversationStore.logs`。旧 `Message`、`ActivityEvent`、`LogEntry` 和历史兼容解析均保留。

Tool 名称、分类、图标和测试命令识别统一由 `ToolPresentation` 提供。

**iOS → Pi：**
```
iOS 发送 agent.input → WS → Extension → pi.sendUserMessage() → Pi Agent
```

**Pi → iOS：**
```
Pi Agent 事件 → Extension 监听 → ProtocolHandler 生成 JSON → WS broadcast → iOS
```

## 7. 设计决策

- **不使用模拟键盘方案**：通过 Pi Extension API 直接注入消息
- **不使用远程桌面方案**：消息级同步，而非屏幕级
- **本地开发**：端口 3001，局域网内直连
- **Push 通知**：iOS 本地通知（`UNUserNotificationCenter`），无需服务器/账号
