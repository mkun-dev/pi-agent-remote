# 通信协议

> JSON over WebSocket，默认端口 3001

## 1. 基础结构

所有消息为 JSON 对象：

```json
{
  "id": "msg_xxx",
  "type": "agent.input",
  "timestamp": 1725000000000,
  "payload": {}
}
```

| 字段 | 类型 | 说明 |
|------|------|------|
| `id` | string | 消息唯一 ID |
| `type` | string | 消息类型（见下表） |
| `timestamp` | number | Unix 毫秒时间戳 |
| `payload` | object | 消息内容 |

## 2. 消息类型总览

| type | 方向 | 说明 |
|------|------|------|
| `agent.input` | iOS → Pi | 用户输入 |
| `agent.output` | Pi → iOS | 兼容消息 / 流式思考增量 |
| `assistant.start` | Pi → iOS | Assistant 正文流开始 |
| `assistant.delta` | Pi → iOS | Assistant 正文增量 |
| `assistant.end` | Pi → iOS | Assistant 正文流完成（含权威完整文本） |
| `agent.status` | Pi → iOS | 状态（running / idle） |
| `tool.start` | Pi → iOS | 工具调用开始 |
| `tool.output` | Pi → iOS | 工具流式输出 |
| `tool.end` | Pi → iOS | 工具调用结束 |
| `file.change` | Pi → iOS | 文件变更（Phase 2） |
| `session.info` | Pi → iOS | 会话信息（Phase 3） |
| `session.update` | Pi → iOS | 会话变化通知（Phase 3） |
| `session.history` | Pi → iOS | 会话历史回放（Phase 3.5） |
| `session.resume` | iOS → Pi | 请求恢复会话（Phase 3） |
| `session.list` | iOS → Pi | 请求历史会话列表（Phase 4） |
| `session.list_result` | Pi → iOS | 历史会话列表（Phase 4） |
| `session.switch` | iOS → Pi | 切换当前窗口到指定会话（Phase 4） |
| `session.switch_ack` | Pi → iOS | 会话切换结果（Phase 4） |
| `relay.status` | 中继 → iOS | agent（PC）在线状态（Phase 3 NAT 穿透） |
| `relay.ack` | 中继 → iOS | 消息已转发确认（Phase 3 NAT 穿透） |
| `relay.error` | 中继 → iOS | 转发失败（agent 离线）（Phase 3 NAT 穿透） |
| `relay.agents` | 中继 → iOS | 在线窗口完整列表（Phase 4） |
| `relay.agent_join` | 中继 → iOS | 窗口上线增量（Phase 4） |
| `relay.agent_leave` | 中继 → iOS | 窗口下线增量（Phase 4） |

## 3. 消息详解

### 3.1 agent.input（iOS → Pi）

```json
{ "type": "agent.input", "payload": { "text": "帮我分析一下这个项目" } }
```

### 3.2 agent.output（Pi → iOS）

```json
{ "type": "agent.output", "payload": { "text": "我正在分析...", "type": "thinking" } }
{ "type": "agent.output", "payload": { "text": "⚠️ LLM 错误: ...", "type": "message" } }
```

- `type: "thinking"`：流式思考增量
- `type: "message"`：兼容消息、命令结果或错误提示
- Assistant 正常正文改由 `assistant.start/delta/end` 发送

### 3.3 assistant.*（Pi → iOS，正文 Streaming）

```json
{ "type": "assistant.start", "payload": { "messageId": "assistant_xxx" } }
{ "type": "assistant.delta", "payload": { "messageId": "assistant_xxx", "seq": 1, "text": "这个项目" } }
{ "type": "assistant.delta", "payload": { "messageId": "assistant_xxx", "seq": 2, "text": "主要包含以下模块" } }
{ "type": "assistant.end", "payload": { "messageId": "assistant_xxx", "text": "这个项目主要包含以下模块" } }
```

- 来源：Pi `message_start` / `message_update(text_delta)` / `message_end`
- `assistant.delta` 是增量文本，扩展端按约 20ms 批量发送；`seq` 从 1 递增，iOS 忽略重复或乱序增量
- `assistant.end.payload.text` 是 `message_end` 的权威完整文本，iOS 用它校正最终内容
- Relay Agent 重连后会主动发送 `session.info`、`session.history` 和当前 `agent.status`，恢复断线期间丢失的状态
- 同一 Agent 回合可以有多个 assistant 流（例如工具调用前说明 + 工具完成后的最终回答）
- `turn_end` 不再重复发送完整正文，避免重复消息

### 3.4 agent.status（Pi → iOS）

```json
{ "type": "agent.status", "payload": { "status": "receiving", "description": "Pi 收到请求" } }
{ "type": "agent.status", "payload": { "status": "thinking", "description": "Pi 正在思考" } }
{ "type": "agent.status", "payload": { "status": "using_tool", "tool": "bash", "description": "npm test" } }
{ "type": "agent.status", "payload": { "status": "completed", "description": "Pi 已完成" } }
{ "type": "agent.status", "payload": { "status": "error", "description": "错误原因" } }
{ "type": "agent.status", "payload": { "status": "idle" } }
```

状态来源：

- iOS 发送普通消息：客户端立即进入 `receiving`
- `before_agent_start`：`receiving`
- `agent_start`：`thinking`
- `tool_execution_start`：`using_tool`
- 最后一项 `tool_execution_end`：`thinking`
- `assistant.delta`：iOS Reducer 直接进入 `streaming`，独立状态区隐藏
- `agent_end`：`completed`，iOS 显示 2 秒后转为 `idle`
- LLM `stopReason=error`：`error`

旧版 `running` 状态仍由 iOS Reducer 兼容映射为 `thinking`。

### 3.5 tool.*（Pi → iOS）

```json
{ "type": "tool.start",  "payload": { "tool": "bash", "command": "ls -la", "toolCallId": "call_xx" } }
{ "type": "tool.output", "payload": { "data": "PASS\nTests completed" } }
{ "type": "tool.end",    "payload": { "success": true } }
```

### 3.6 file.change（Pi → iOS，Phase 2）

```json
{
  "type": "file.change",
  "payload": {
    "path": "src/main.ts",
    "action": "modified",
    "additions": 12,
    "deletions": 3
  }
}
```

- `action`：`modified` | `created` | `deleted`
- `additions` / `deletions`：可选；工具无法可靠提供统计时省略
- 触发：`tool_execution_start` 缓存 args 和目标文件轻量快照，成功的 `tool_execution_end` 提取路径并广播
- `edit` 优先解析工具结果中的 unified patch；`write` 根据写入前状态判断新增/修改，并使用内容行数生成摘要
- 只处理写入类工具，`read` / `grep` / `find` 不产生文件变化事件；不使用文件系统 watcher 或项目扫描

### 3.7 session.*（Phase 3）

**session.resume（iOS → Pi）**——iOS 连接/重连后请求恢复：
```json
{ "type": "session.resume", "payload": { "sessionId": "019fdc..." } }
```

**session.info（Pi → iOS）**——响应 resume 请求：

```json
{
  "type": "session.info",
  "payload": {
    "sessionId": "019fdc14-...",
    "sessionFile": "C:\\Users\\...\\sessions\\....jsonl",
    "name": null,
    "leafId": "...",
    "entryCount": 2,
    "reason": "startup"
  }
}
```

**session.history（Pi → iOS，Phase 3.5）**——随 session.info 一起回放对话历史（最多 100 条）：

```json
{
  "type": "session.history",
  "payload": {
    "sessionId": "019fdc14-...",
    "entries": [
      { "entryId": "entry-a:user", "sessionId": "019fdc14-...", "role": "user", "text": "帮我分析这个项目", "ts": 1725000000000 },
      { "entryId": "entry-b:assistant", "sessionId": "019fdc14-...", "role": "assistant", "text": "好的，我来看看...", "ts": 1725000010000 },
      { "entryId": "entry-b:tool:call-1", "sessionId": "019fdc14-...", "role": "tool", "text": "bash ls -la", "ts": 1725000020000 },
      { "entryId": "entry-c:terminal", "sessionId": "019fdc14-...", "role": "terminal", "text": "src/\nREADME.md", "ts": 1725000030000 }
    ]
  }
}
```

- `role`：`user` | `assistant` | `tool` | `terminal`
- `entryId`：复用 Pi `SessionEntry.id` 并为同一条目拆出的正文、Tool、输出增加稳定后缀
- `sessionId` + `entryId` + `ts` 在连续重连时保持稳定
- 来源：Pi session 文件主分支（`buildContextEntries`，含 compaction 处理），assistant 的 text 与 toolCall 拆成多条
- `session.history` 是当前 Session 的权威快照；空会话也发送空数组
- iOS 端以快照替换/去重当前历史，不再直接 append；历史消息静态渲染（不走打字动画）

**session.list（iOS → Pi，Phase 4）**——请求目标窗口列出磁盘上的历史会话：

```json
{ "type": "session.list", "payload": { "targetAgentId": "win-abc12345" } }
```

**session.list_result（Pi → iOS，Phase 4）**：

```json
{
  "type": "session.list_result",
  "payload": {
    "sessions": [
      { "path": "C:/.../sessions/xxx.jsonl", "id": "019fdc...", "name": null,
        "cwd": "D:/project", "messageCount": 12, "firstMessage": "...", "modified": 1725000000000 }
    ]
  }
}
```

**session.switch（iOS → Pi，Phase 4）**——让目标窗口切换到指定历史会话（内部执行 `ctx.switchSession`，窗口会话重启后 agentId 不变）：

```json
{ "type": "session.switch", "payload": { "sessionFile": "C:/.../sessions/xxx.jsonl", "targetAgentId": "win-abc12345" } }
```

**session.switch_ack（Pi → iOS，Phase 4）**——`{ "payload": { "sessionFile": "...", "ok": true } }`；iOS 收到后延迟重新 `session.resume` 拉取新会话历史。

**session.update（Pi → iOS）**——会话变化通知：

```json
{ "type": "session.update", "payload": { "reason": "startup|renamed|tree|...", ...同上 } }
```

触发时机：`session_start`（startup/reload/new/resume/fork）、`session_info_changed`（改名）、`session_tree`（分支导航）。

### 3.8 relay.*（中继服务器，Phase 3 NAT 穿透 + Phase 4 多窗口）

**多窗口架构**：中继维护 `Map<agentId, ws>`，每个 PC 窗口（Pi 实例）是一个 agent，用**窗口稳定 ID**（`win-xxxxxxxx`，进程生命周期不变）注册；iOS 选择目标窗口对话，消息带 `targetAgentId` 路由。

**relay.agents（中继 → iOS）**——client 连接或 agent 变化时推送完整窗口列表：

```json
{
  "type": "relay.agents",
  "payload": {
    "agents": [
      { "agentId": "win-abc12345", "name": "重构模块", "cwd": "D:/project", "model": null, "online": true },
      { "agentId": "win-def67890", "name": null, "cwd": "D:/other", "model": null, "online": true }
    ]
  }
}
```

**relay.agent_join / relay.agent_leave（中继 → iOS）**——窗口上下线增量：

```json
{ "type": "relay.agent_join",  "payload": { "agent": { "agentId": "win-...", "name": "...", "cwd": "..." } } }
{ "type": "relay.agent_leave", "payload": { "agentId": "win-..." } }
```

**消息路由**：client 发消息时 payload 带 `targetAgentId`（如 `agent.input`、`session.resume`、`session.list`、`session.switch`），中继转发给指定窗口；不带则转发给第一个在线窗口（兼容旧版）。

**relay.status（中继 → iOS）**——agent 在线状态变化：

```json
{ "type": "relay.status", "payload": { "status": "agent_online" | "agent_offline" } }
```

- client 连接中继时立即推送一次当前状态
- agent 上线/下线时推送

**relay.ack / relay.error（中继 → iOS）**——消息送达确认：

```json
{ "type": "relay.ack",   "payload": { "id": "msg_xxx" } }
{ "type": "relay.error", "payload": { "id": "msg_xxx", "code": "agent_offline" } }
```

- client 发的每条带 `id` 的消息，中继转发给 agent 成功后回 `relay.ack`
- agent 不在线时回 `relay.error`（iOS 显示"PC 离线"）
- iOS 端 10 秒未收到确认 → 本地标记"未送达"

**连接鉴权**：

- iOS 与 Extension 发送 `Authorization: Bearer <token>`；Token 不再放入 URL
- iOS URL 携带非敏感 `role=client&client_id=<稳定设备ID>`
- Extension URL 携带 `role=agent&agentId=<窗口ID>`
- Token 缺失/错误 → 4001；role 错误 → 4002；client_id 无效/未绑定 → 4003
- Relay 可通过 `RELAY_CLIENT_ID` 绑定唯一设备；同一时间只允许一个 client
- URL Token 仅为旧客户端兼容，可用 `ALLOW_QUERY_TOKEN=0` 关闭
- 局域网 3001 与公网 Relay 复用同一个 Token

**media.upload 安全边界**：

- 客户端 `dir` 与 `fileName` 不参与最终落盘路径
- 固定保存到当前项目的 `pi-ios-uploads/`
- 服务器生成 UUID 随机文件名
- `resolve` 后校验文件必须位于允许目录
- 仅接受受支持的图片签名，单图最大 10 MB
- WebSocket 单消息默认最大 20 MB

## 4. 扩展端实现要点

- **事件字段名**：`tool_execution_start/update/end` 的输入参数在 `args` 字段（不是 `input`）
- **`tool_execution_end` 没有 `args`**：用 `Map<toolCallId, args>` 在 start 时缓存，end 时取出
- **会话持久化**：`pi.appendEntry("ios-session", info)` 写入 session 文件，重启可恢复
- **历史回放**：`session.resume` 时用 `buildContextEntries()` 提取主分支历史，随 `session.info` 一起回 `session.history`
- **多窗口**：中继连接用窗口稳定 ID（`win-` 前缀），会话切换（/new、/resume、switchSession）不改变 agentId，iOS 对话目标不变
- **会话管理**：`session.list` 用 `SessionManager.list(ctx.cwd)` 列历史会话；`session.switch` 用 `ctx.switchSession(path)` 切换窗口会话
- **生命周期**：WS 服务器在 `session_start` 启动、`session_shutdown` 关闭（遵循 Pi 扩展规范）

## 5. 端口与地址

- 监听：`ws://0.0.0.0:3001`
- iOS 模拟器：`ws://localhost:3001`
- iOS 真机：`ws://<PC局域网IP>:3001`
