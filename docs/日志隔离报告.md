# 日志隔离报告：内部日志 ≠ Agent Conversation

> 任务：彻底隔离内部系统日志与 Agent Conversation，禁止内部日志进入聊天窗口。
> 方法：先审查真实链路（不假设），再实施「分类 + 过滤层 + 分级」，保持真实调试能力不丢失。
> 日期：2026-08-12

---

## 1. 日志污染根因（审查结果）

### 根因 A：Extension 调试日志输出到 Pi 进程 stdout（已删除，等待 PC 端更新）

用户看到的日志（`[workspace] readFile 成功`、`[MODEL] request`、`[workspace] list 请求/成功`）是 **Extension 旧版代码中的 `console.log`**：

```
旧版 Extension console.log（[workspace]/[MODEL] 等前缀）
→ Pi 进程 stdout（extension 运行在 Pi 进程内）
→ Pi TUI / 终端显示（用户感知为「聊天窗口出现日志」）
```

**当前代码已不存在这些字符串**（全仓 grep 验证）。它们属于「请求/成功信息」类调试日志，在日志静默化改动中已删除 11 条（`[USAGE] broadcast`、`[MODEL] command/list/request/select_ack`、`[workspace] list 请求/成功`、`readFile 成功`、`search`、`[AGENT] relay connect`）。

> ⚠️ 若 PC 端仍看到这些日志，说明 Pi 加载的是旧版扩展——需更新 PC 端扩展代码并重启 Pi。

### 根因 B：`pi.appendEntry("ios-session", ...)` 写入 Agent 会话文件（本次已移除）

Extension 在 `session_start` 时调用 `pi.appendEntry("ios-session", info)`，会在 **Pi 的 Session 分支中创建 custom 条目**并写入会话文件：

```
pi.appendEntry("ios-session", info)
→ SessionManager.appendCustomEntry → type:"custom" 条目写入 session 文件
→ Pi TUI 会话历史可见（内部状态混入 Agent 会话）
→ 不参与 LLM context（Pi 文档确认）→ 不进 iOS history（buildHistory 只投影 message/compaction）
```

属于「内部状态写入 Agent 会话」的架构污染。`"ios-session"` 全仓无任何读取方，**本次已安全移除**（会话状态本就通过 `session.info/session.update` 实时同步，无需持久化到 Agent 会话文件）。

### 根因 C：iOS 侧无防御性白名单（本次已加固）

审查确认 iOS `ConversationStore` 现状已正确——`workspace.* / model.* / usage.* / agent.status / relay.* / session 元数据` 只更新 `@Published` 状态投影，**不生成 Message**（聊天消息只来自 `agent.input/output`、`assistant.*`、`tool.*`、`file.change`、`media.image`、`session.history`）。但没有**统一白名单契约层**：未来新增事件类型若直接 append 到 messages，会静默污染聊天。

## 2. 修复前错误数据流

```
（A）Extension console.log（旧版）
     └→ Pi stdout → TUI 显示 ← 用户看到的 [workspace]/[MODEL] 日志
（B）pi.appendEntry("ios-session")
     └→ Session 分支 custom 条目 → Pi TUI 会话历史显示
（C）iOS 无白名单 → 未来新事件默认可能进 messages（潜在风险）
```

## 3. 修复后正确数据流

```
内部日志（workspace/model/usage/relay/transport）
     ├→ Extension console（错误才保留 console.error；成功/请求类已删）
     ├→ Relay log（RELAY_DEBUG=1 才输出，服务器侧）
     └→ iOS RemoteLogger（OSLog，按 LogLevel 分级）
             └→ 只进 Console / Debug Panel / File Log —— 绝不进 messages

Agent Conversation 只接收白名单事件：
     agent.input / agent.output(功能反馈) / assistant.* / tool.*
     / file.change / media.image / session.history
```

## 4. 新日志分层架构

| 层 | 通道 | 允许内容 | 默认 |
|----|------|----------|------|
| **User Conversation** | 聊天消息列表 `messages` | `agent.input`、`assistant.*`、`tool.*`、`file.change`、`media.image`、`session.history`、`agent.output`（功能反馈） | ✅ 允许 |
| **System Event** | 状态投影 `@Published` | `agent.status`、`session.info/update/list/switchAck`、`questionnaire.*` | ✅ 允许（不进聊天） |
| **Debug Log** | Console / Debug Panel / File Log | `workspace.*`、`model.*`、`usage.*`、`relay.*`、transport 调试 | Debug 构建可见，Release 关闭 |

### 日志分级（第六阶段，iOS `RemoteLogger`）

```swift
enum LogLevel: Int, Comparable { case debug, info, warning, error }
// Debug 构建: minimumVisibleLevel = .debug   （开发模式：允许 [WORKSPACE]/[MODEL]/[USAGE]）
// Release 构建: minimumVisibleLevel = .warning（用户环境：调试日志一律关闭）
```

日志只影响 Console 输出；聊天消息列表始终不接收任何日志（OSLog 通道与 messages 完全分离）。

## 5. Conversation 过滤规则（第七阶段）

新增 `ConversationMessageFilter`（`pi-ios-app/PiAgentRemote/Models/ConversationMessageFilter.swift`）：

```swift
enum ConversationMessageFilter {
    static func allowsMessageEntry(_ payload: RemoteEvent.Payload) -> Bool
    static func kind(of payload: RemoteEvent.Payload) -> EntryKind  // conversation / systemEvent / debugLog
}
```

**白名单（允许进入消息列表）**：`agent.input`、`agent.output`、`assistant.start/delta/end`、`tool.start/output/end`、`file.change`、`media.image`、`session.history`。

**拒绝（只更新状态投影 / 仅 Debug 通道）**：`workspace.*`、`model.*`、`usage.*`、`relay.*`、`agent.status`、`session.info/update/list/switchAck`、`questionnaire.*`、`unknown`。

**默认拒绝原则**：未来协议新增事件类型必须显式加入白名单才能进入聊天，防止内部日志混入用户聊天。

集成点：`ConversationStore.accept()` 事件分发前执行白名单判定，非白名单事件输出 `[FILTER]` DEBUG 日志（`#if DEBUG`），确认其只走状态投影。
